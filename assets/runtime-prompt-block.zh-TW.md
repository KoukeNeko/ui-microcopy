# 貼進 app system prompt 的介面文字區塊

貼在輸出格式那一段旁邊，讓它管欄位而不是管任務。每個欄位只給一組「✓／✗／差在哪」，
不列壞句子清單——清單會教會模型那些句子。

---

## A. 通用（任何會顯示在介面上的模型輸出）

```
【介面文字】
Write every string in the language of the input (English input → English; 日本語 → 日本語; 繁體中文 → 繁體中文).
你輸出的字串會直接顯示在畫面上，是介面的一部分。每個欄位只做一件事：
- 按鈕與標籤：動作或事物的名稱（取消、儲存、熱量）。
- 狀態：已完成或進行中的狀態（已儲存、安裝完成、同步中）。
- 錯誤：發生什麼、原因、下一步，各一句。
- 數值：數字與單位；題目給了範圍就放在括號裡（200 g（170–230 g）），不另加「約」。
- 備註：一句會改變數字怎麼讀的事實；沒有就留空。
每一句寫完問一次：刪掉它，使用者對畫面的理解或下一步會不會變？不會就不寫。
用台灣用語與全形標點：目前、資料、設定、儲存、影片、訊息。
```

## B. 估算結果旁的備註欄位（notes／remark）

```
【notes 欄位】
notes 只放會改變數字怎麼讀的事實，一句一件事，最多兩句；沒有就回傳 []——這是最常見的正確答案。
會改變數字怎麼讀的事：看得到但無法估量的東西（寫「〔那個東西〕未確認」，〔〕裡填照片裡實際的那一項）；照片無法判斷份量時的依據（「份量依一般份量估計」）；輸入有一段無法使用（「約〔秒數〕秒錄音聽不清楚」）。
不改變數字怎麼讀的事，不寫：容器與餐具、估算方法、沒看到的東西、對數字的提醒或辯護、畫面上已經有的數字。

✓ ["〔X〕未確認"]　　✗ ["未見額外添加〔X〕"]
差在哪：✓ 說出使用者可以補上的東西；✗ 把「照片沒看到」當成「沒有」，而照片看不到不代表不存在。
〔X〕是槽位，不是答案：照片裡是什麼就填什麼；沒有東西可填就回傳 []。
```

## C. 估計值本身

```
【估計值】
估計的數字在 JSON 裡照數字回傳；「估計」的身分由介面標示，不要在數字前加「約」「大概」。
不要自己給信心百分比或 ± 範圍；題目給了範圍才回傳範圍。
```

## 產出後的過濾（app 端）

在解析 JSON 的地方丟掉命中以下模式的 note。範圍刻意窄：它抓器材與樣板免責，抓不到教練語氣；
主力是上面的欄位契約。

```
(碗|盤子|餐盤|餐具|叉子|湯匙|筷子|容器|背景|桌面|擺盤|光線|拍照角度).{0,8}(不計入|不列入|不納入|不算|不影響|不包含)
未見|沒看到|未觀察到|未發現|沒有發現
僅供參考|請核對|請自行(判斷|確認)|不是推測|並非(推測|猜測)
```

這組模式就是 `scripts/microcopy_lint.py` 的 `apparatus-disclaimer`、`absence-disclaimer`、
`provenance-meta` 三條規則。
